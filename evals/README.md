# evals：自检脚本的回归测试

`scripts/check_output.py` 是交付前的最后一道关，它自己也可能错。一个"永远说通过"的
自检脚本比没有自检更糟，因为它会让人以为查过了。这个目录用来钉死它的判定行为：
**合格骨架必须放行，故意做坏的样本必须拦住。**

## 目录

| 路径 | 作用 |
|---|---|
| `fixtures/good-minimal.md` | 论文精讲骨架：10 节齐全、两个步骤三段式、`式(n)` 与速查表对齐、3 张编号表、1 张插图、5 个 FAQ、出处标注齐全。**它不是成品**，只有一千多字，用来单独验证结构性判定 |
| `fixtures/fig-sample.png` | 骨架样本引用的那张插图（十几 KB 的框图），用来验证 S14/S15；没有它导出脚本会报缺图 |
| `fixtures/brief.md` | 速览模式样本，约 800 字，用来验证 `--profile brief` |
| `fixtures/algorithm-minimal.md` | 算法详解骨架：0～9 章、符号/地图章、多章含公式与手算、`> **通俗解释**` 风格，用来验证 `--profile algorithm` 与 A0–A8 |
| `run_evals.py` | 跑全部案例，比对退出码 |

## 怎么跑

```bash
python evals/run_evals.py            # 只看结论
python evals/run_evals.py --verbose  # 连每个案例命中的 FAIL/WARN 一起打印
```

退出码 0 = 全部符合预期，1 = 有案例不符合预期。当前 **13 个案例全绿**。

## 每个案例在钉死什么

| 案例 | 期望 | 命中的检查 |
|---|---|---|
| 论文骨架 + 放宽阈值（`--min-total 300 --min-method 100 --skip-share`） | 0 | S1–S15 全部应该通过 |
| 同一份骨架 + 默认阈值（4500 字） | 1 | S6a/S6b/S6c —— 证明阈值真的在生效 |
| 速览样本 + `--profile brief` | 0 | 只查速览结构、600 字下限、禁用词、占位符 |
| 算法骨架 + `--profile algorithm` + 放宽阈值 | 0 | A0–A8 全部应该通过 |
| 算法骨架删到 4 章 | 1 | A1 章数/连续性 |
| 算法骨架插入"同理" | 1 | S5 禁用词（算法模式也查） |
| 论文骨架删掉第4节 | 1 | S1 节完整性 |
| 论文骨架在第5节插入"显然" | 1 | S5 禁用词 |
| 论文骨架删掉第一个【数字例子】 | 1 | S3 三段式缺失 + S4 公式无例子 |
| 论文骨架速查表删掉 式(2) 那一行 | 1 | S9 编号不一致 |
| 论文骨架删光所有表格 | 1 | S13 表格不足 |
| 论文骨架删掉所有插图 | 1 | S14 没有插图 |
| 论文骨架第6节留一行 TODO | 1 | S12 占位符 |

## 为什么骨架样本要配放宽阈值

骨架样本是"结构对、内容短"，默认阈值（4500 字 / 方法部分 2600 字 / 占比 55%）当然会失败。
用 `--min-total 300 --min-method 100 --skip-share` 把篇幅判定摘掉，剩下的失败就只可能来自结构问题，
排查时不会被字数噪音淹没。

注意算法模式下的"方法部分"指**含公式的那些章合计**，不是某一节；所以 A4 与 S6b 报的是同一个数，
两条都失败时改一处即可。

## 加新检查项时的规矩

1. 在 `scripts/check_output.py` 里新增一个 `Sxx` / `Axx` 检查；
2. 在 `run_evals.py` 的 `CASES` 里至少加一个**反例**（故意触发它的变体）；
3. 确认骨架样本仍然给 0——新检查不能误伤合格输出。

骨架样本里已经预置了 3 张表 + 1 张图，删表/删图的变体就是 S13/S14 的反例；加需要素材的新检查项时，记得同步给骨架样本补素材。

没有反例的检查项等于没有检查。这条规矩就是为了防止"又加了一条没人验证的规则"。

## 和 lint_skill.py 的分工

| 脚本 | 查什么 | 什么时候跑 |
|---|---|---|
| `scripts/lint_skill.py` | **技能本身**自洽：三份规则副本一致、资源路径存在、术语库索引与分册同步 | 改完技能文件之后 |
| `scripts/check_output.py` | **成品**合格：一篇精讲出来之后是否达标 | 每次交付精讲之前 |
| `evals/run_evals.py` | **上面两个脚本**里 check_output 的判定是否正确 | 改过 check_output.py 之后 |
