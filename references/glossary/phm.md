# 术语分册：PHM 全链路

> PHM（Prognostics and Health Management，故障预测与健康管理）是用户方向的总框架。这册从"数据怎么来"走到"什么时候该修"。
> 每行 = 术语 | 一句话定义 | 生活化比喻 | 在论文/工程里的位置。

| 术语 | 一句话定义 | 生活化比喻 | 在论文/工程里的位置 |
|---|---|---|---|
| PHM | 用数据与模型评估设备健康、预测故障、指导维修决策的整套体系 | 给设备配一个会体检、会预判、会定复查日期的私人医生 | 所有诊断/预测工作的上位框架 |
| 状态监测（Condition Monitoring） | 持续采集振动、温度、电流等信号以掌握设备状态 | 24 小时戴着的健康手环 | 数据来源层，决定后面一切的上限 |
| 故障诊断（Diagnosis） | 判断"现在有没有故障、是什么故障、在哪" | 医生看片子下诊断 | 分类问题的本质 |
| 故障预测 / 预测（Prognosis） | 判断"故障什么时候会发生、还能撑多久" | 天气预报：明天会不会下雨 | 回归/时序问题的本质 |
| 健康指标（Health Indicator, HI） | 一个随退化单调变化的标量，越大越糟 | 体检报告里的综合评分 | 把多维信号压成一维趋势，供 RUL 预测 |
| 退化建模（Degradation Modeling） | 用数学模型描述 HI 随时间的演变规律 | 描述轮胎磨损的曲线 | 指数模型、随机过程、Wiener 过程常用 |
| 剩余寿命（RUL） | 从当前时刻到失效还剩多少时间/循环数 | 手机电量还能用几小时 | PHM 的核心输出量，通常带置信区间 |
| 不确定性量化（UQ） | 给预测结果配一个可信范围 | 不仅说明天下雨，还说"70% 概率" | 贝叶斯方法、集成、分位数回归服务于它 |
| 失效阈值（Failure Threshold） | 判定"已失效"的 HI 临界值 | 体检指标的"红线值" | 定低了误报、定高了漏报，是策略参数 |
| 首预测时刻（First Predicting Time） | 退化开始可被检测到的时刻 | 症状第一次能被量出来的那天 | 决定训练样本的起点，早期检测难度最大 |
| 加速寿命试验（ALT） | 加大应力让设备快速失效，再折算到正常工况 | 用高压锅加速食物变质来估算保质期 | 实验室获取退化样本的常用手段 |
| 全生命周期数据 | 从出厂到报废的完整记录 | 一个人的完整病历 | 越完整越能训练可靠的预测模型 |
| 预防性维护（Preventive） | 按固定周期修 | 每 5000 公里换机油 | 简单可靠，但常常"修早了" |
| 预测性维护（Predictive） | 按预测结果安排维修 | 车自己告诉你该换刹车片了 | PHM 的经济价值所在 |
| 视情维护（CBM） | 依据实时状态触发维护 | 看仪表盘决定要不要停车 | 预测性维护的工程落地形态 |
| 维修决策优化 | 在成本、停机损失、风险之间选最优维护时机 | 权衡"现在修耽误生产"和"坏了损失更大" | 把 RUL 变成钱的那一步 |
| 故障模式（Failure Mode） | 故障的具体表现形式与机理 | 感冒 vs 骨折，都是病但机理不同 | 多分类诊断的类别定义依据 |
| 故障严重程度（Severity） | 同一故障模式下损伤的程度分级 | 轻微擦伤 vs 深划伤 | 分级诊断比"有无故障"更有工程价值 |
| 复合故障（Compound Fault） | 多个故障同时存在、信号互相叠加 | 同时感冒又胃疼 | 传统单标签分类会失效，需要多标签/解耦 |
| 耦合（Coupling） | 两个部件/故障之间互相影响 | 两根缠在一起的绳子，拉一根另一根也动 | 用户研究对象（带电摩擦副）的核心难点 |
| 变工况（Variable Working Condition） | 转速、负载等运行条件在变化 | 同一辆车在市区和高速的不同表现 | 特征分布随工况漂移，是泛化失败的主因 |
| 域偏移（Domain Shift） | 训练分布与测试分布不一致 | 在南方学的驾驶经验拿到北方雪地 | 跨设备、跨工况诊断要解决的根问题 |
| 跨域诊断（Cross-Domain Diagnosis） | 用 A 设备/工况的数据诊断 B | 把老医生的经验带到新医院 | 迁移学习在 PHM 的主战场 |
| 开集诊断（Open-Set） | 测试时出现训练中没见过的故障类型 | 遇到没见过的病也要说"我不认识" | 比闭集分类更贴近现场 |
| 小样本故障诊断 | 每类只给几个样本 | 只看过三张片子就要会看诊 | 新故障、昂贵故障的常态 |
| 数字孪生（Digital Twin） | 用模型在计算机里同步复制一台真实设备 | 给设备做个"虚拟双胞胎"做试验 | 缺数据时用孪生体生成仿真故障样本 |
| 仿真数据 / 迁移仿真到实物 | 用物理模型造数据再迁移到实测 | 先在模拟器上练，再上真机 | 解决"故障样本拿不到"的主流思路 |
| 数据驱动 vs 机理驱动 | 靠数据学规律 vs 靠物理方程推演 | 老中医经验 vs 西医化验 | 论文的创新点常在这两者之间做混合 |
| 端到端（End-to-End） | 原始信号直接进、诊断结果直接出 | 从原料到成品一条线，不设中间仓库 | 省去手工特征工程，但可解释性变差 |
| 可解释诊断 | 结论能对应到具体频率/部件/时间段 | 医生能指出片子上的病灶位置 | 工业落地与安全审查的硬要求 |
| 边缘部署（Edge Deployment） | 模型跑在设备旁的小算力盒子上 | 把诊所开到村口 | 参数量、时延、内存是硬约束 |
| 在线 / 离线诊断 | 边采边判 vs 采完再算 | 直播 vs 录播 | 在线要求低延迟，离线可以堆复杂模型 |
| 数据集划分（按设备/按时间） | 训练测试怎么切才不泄漏 | 考试不能考原题 | 按设备切比随机切更接近真实泛化 |
| 台架数据 vs 现场数据 | 实验台采集 vs 真实设备采集 | 驾校场地 vs 真实马路 | 两者分布差距是迁移诊断的主要障碍 |

## 数字例子模板（HI → RUL 的简化）

某轴承 HI 序列（越大越坏）：t=1..5 时 HI = [0.10, 0.14, 0.21, 0.33, 0.52]。
设失效阈值 1.0，用指数外推 HI(t) = 0.10·e^{0.32t}：
t=5 时 0.10·e^{1.6} ≈ 0.495（与观测接近）。
解 0.10·e^{0.32t} = 1.0 → t ≈ ln(10)/0.32 ≈ 7.2。
所以当前时刻 RUL ≈ 7.2 − 5 ≈ 2.2 个时间单位。
**读法**：RUL 预测 = "拟合退化曲线 + 解方程求交点"，难点全在曲线形状选得对不对、噪声怎么压。
