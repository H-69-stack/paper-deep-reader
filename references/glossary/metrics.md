# 术语分册：评价指标与实验设计

> 论文第 5 节的所有数字都在这册里。看不懂指标，就分不清"真的更好"和"被平均掩盖"。
> 每行 = 术语 | 一句话定义 | 生活化比喻 | 论文里一般在哪出现。

| 术语 | 一句话定义 | 生活化比喻 | 论文里一般在哪出现 |
|---|---|---|---|
| 混淆矩阵（Confusion Matrix） | 把预测与真实按类别交叉计数 | 一张"诊断对了几个、错判成什么"的账本 | 多分类诊断必报，比单一准确率信息量大 |
| 准确率（Accuracy） | 判对的比例 | 一百道题对几道 | 类别均衡时可用，不平衡时会被"全判正常"骗到 99% |
| 精确率（Precision） | 报出来的故障里有多少是真的 | 报警 10 次真出事几次 | 误报代价高时看它 |
| 召回率（Recall） | 真实故障里抓到了多少 | 真出事 10 次报出几次 | 漏报代价高时看它（工业上通常更看重） |
| F1 分数 | 精确率与召回率的调和平均 | 既要少误报又要少漏报的综合分 | 不平衡数据集的默认汇报指标 |
| 宏平均 / 微平均（Macro / Micro） | 每类先算再平均 / 全部样本一起算 | 各班平均分 / 全年级平均分 | 多类不平衡时两者差别很大，论文必须说明用哪个 |
| ROC 曲线 / AUC | 阈值扫一遍得到的 TPR-FPR 曲线及其面积 | 撒网大小与漏鱼多少的权衡图 | AUC=0.5 等于瞎猜，1.0 完美 |
| PR 曲线 / AP | 精确率-召回率曲线及其面积 | 同上，但对不平衡更敏感 | 故障类稀少时比 AUC 更能反映真实水平 |
| 混淆矩阵衍生的误报率 / 漏报率 | 误报率 = FP/(FP+TN)，漏报率 = FN/(FN+TP) | 狼来了喊错 / 真狼没喊 | 工程验收常直接卡这两个数 |
| 检测延迟（Detection Delay） | 从故障发生到被检出的时间差 | 火灾从起火到报警的时间 | 在线监测的关键指标，越短越好 |
| MAE / MSE / RMSE | 回归误差的绝对/平方/均方根平均 | 预测值偏离真实值多远 | RUL 预测的常用误差指标 |
| MAPE | 平均绝对百分比误差 | 偏离相对多少（百分比） | RUL 量级差异大时用，但真值接近 0 时会爆 |
| R²（决定系数） | 模型解释了目标多少比例的变化 | 预测能解释现实的百分之多少 | 回归任务的补充指标，可为负（比均值还差） |
| 评分函数（Score Function, PHM08） | 对 RUL 预测误差按"早测/晚测"不对称惩罚 | 晚预测比早预测罚得更重 | IEEE PHM 2012 挑战赛的官方指标，论文常引用 |
| 覆盖率（Coverage） | 置信区间包含真值的比例 | 说"70% 概率下雨"，长期看真下多少 | 区间预测质量的度量，需与区间宽度一起看 |
| 平均区间宽度（MPIW） | 置信区间的平均宽度 | 预报的"范围"有多宽 | 覆盖率相同则越窄越好 |
| 时延 / 推理时间（Latency） | 单次预测耗时 | 医生看一张片子要几秒 | 边缘部署章节必报 |
| 参数量（Params） | 模型的权重个数 | 模型的"体重" | 轻量化对比表的第一列 |
| 计算量（FLOPs / MACs） | 一次前向的浮点运算次数 | 干一件事要挥多少次手 | 与参数量一起用来说明"轻" |
| 内存占用 / 显存占用 | 运行时占多少存储 | 工作台占多大 | 边缘部署可行性的硬指标 |
| 消融实验（Ablation Study） | 逐个去掉模块看性能掉多少 | 拆零件看哪个真有用 | 证明"创新模块不是凑数"的唯一手段 |
| 基线（Baseline） | 用来对比的已有方法 | 参照的标尺 | 基线太弱 = 结论不可信，要查它是否公平复现 |
| 随机种子 / 多次重复 | 换种子跑多次报均值±方差 | 多考几次取平均 | 只报单次最好结果的论文要警惕 |
| t 检验 / p 值 | 判断差异是否可能由随机造成 | 差异是真本事还是运气 | 严谨论文会做显著性检验 |
| 交叉验证结果 | k 折平均性能 | 换考官多考几次 | 小样本论文更该报 |
| 混淆对（Confusable Pair） | 经常被互相错判的两类 | 双胞胎总被认混 | 分析误差来源时比总准确率有用 |
| 可视化（t-SNE / 特征分布图） | 把高维特征压到 2D 看类是否分开 | 把人群投影到地面看聚不聚 | 域适应论文的标配图 |
| 学习曲线 / 收敛曲线 | 损失随训练进度的变化 | 练习成绩随时间的走势 | 判断是否过拟合、是否早停 |

## 数字例子模板（混淆矩阵手算）

二分类（有故障/正常），TP=6、FP=2、FN=4、TN=8。
准确率 = (6+8)/20 = 0.70。
精确率 = 6/(6+2) = 0.75；召回率 = 6/(6+4) = 0.60。
F1 = 2×0.75×0.60/(0.75+0.60) = 0.90/1.35 ≈ 0.667。
误报率 = 2/(2+8) = 0.20；漏报率 = 4/(4+6) = 0.40。
**读法**：准确率 0.70 看着还行，但漏掉了 40% 的故障——工业场景里这个模型不能上线。
