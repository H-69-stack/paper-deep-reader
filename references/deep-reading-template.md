# 论文精讲输出模板（Deep Reading Template）

> 本文件定义论文精讲的**强制输出结构**和**质量标准**。执行精讲时必须严格遵守；与 SKILL.md 冲突时以本文件为准。
> 模板、SKILL.md、`assets/deepseek-desktop-agent.json` 三份副本的一致性由 `scripts/lint_skill.py` 断言；成品是否达标由 `scripts/check_output.py` 机械校验。改规则后两个脚本都要能跑通。

## 目录

| 节 | 内容 | 什么时候看 |
|---|---|---|
| 一 | 输出结构：第0～9节 | 每次必读 |
| 二 | 10条硬性要求 | 每次必读 |
| 三 | 公式讲解规范（三段式） | 写第3、4、5节时 |
| 四 | 数字例子设计原则 | 设计手算例子时 |
| 五 | 降级规则 + 18项质量自检清单 | 做不到时、交付前 |
| 六 | 用户研究背景与比喻优先级 | 选比喻时 |
| 七 | 论文类型路由与变体结构 | **读完摘要就要判断** |
| 八 | 标题层级映射与公式编号约定 | 动笔前定层级；写第8节时 |

| 十二 | 图表规范（表格怎么用、插图怎么生成、怎么编号） | 动笔前规划图表；写完补图 |

## 一、输出结构：第0～9节，共10节（必须按此顺序，不得省略、不得调换）

### 第0节：一句话总览

用**不超过3句话**、纯大白话（无任何专业术语）说明：
- 这篇论文在什么场景下
- 用了什么方法
- 解决了什么问题
- 效果如何

### 第1节：这篇论文到底在做什么？（问题背景）

必须包含：
1. **研究对象是什么**：用生活化比喻说明（如"液压电磁阀就像水管的自动水龙头"）
2. **会出什么问题**：为什么需要诊断/分析，不诊断会怎样
3. **以前的人怎么做的**：分阶段简述已有方法，每类方法的核心思路和不足
4. **这篇论文的新思路**：用比喻讲清创新点（如"老医生不仅听诊，还会把多种咳嗽声分开听"）
5. **完整流水线图**：从输入数据到输出结果的每一步（复杂架构用 Mermaid，短流程用 ASCII）

### 第2节：相关概念扫盲（前置知识）

把论文中**影响理解的核心概念**逐个按以下格式讲解（不是把每个名词都堆一遍，判断标准：不懂它就读不懂方法）：

```
### 概念名称（English Term）
- 一句话定义
- 生活化比喻
- 极小数字例子（2-3个数据点）
```

示例格式：
> **什么是域自适应（Domain Adaptation）？**
> - 定义：让在A场景训练的模型，在B场景也能用的技术
> - 比喻：在南方练的车，到北方下雪天也能开
> - 数字例子：源域数据[1,2,3]均值2，目标域数据[4,5,6]均值5，域自适应就是把目标域平移到均值2附近

### 第3节：论文方法逐模块精讲（核心，占全文≥55%）

把方法拆成步骤1、步骤2……**模块顺序和命名与论文一致**，每个步骤严格按**三段式**（层级见"八、标题层级映射"）：

### 步骤X：模块名称

#### 【通俗理解】
- 这一步在流水线中的角色（比喻）
- 输入是什么？输出是什么？
- 为什么需要这一步？跳过会怎样？

#### 【学术公式】
- 完整写出论文公式（LaTeX），公式后标自编号与论文出处，格式：`式(3)（论文式(7)）`
- **逐个符号解释**：每个字母、希腊字母、上下标、括号内容，都用大白话解释
- 公式每一项在"惩罚什么/鼓励什么/约束什么"
- 如有推导，一步步写出中间结果，绝不跳步
- 公式里出现"逐元素乘、转置、期望、范数"等记号时，第一次出现要解释（可查 field-glossary 的符号速查表）

#### 【数字例子】
- 用**极小规模**（2-4个数据点、2×2矩阵、2-3类别）手算
- 每一步计算都写出，包括中间结果
- 最后说明：算出来的结果在实际场景中代表什么

#### 【代码对应】（如能推断）
- Python伪代码
- 标注关键变量与论文公式的对应关系
- 无法推断实现细节时写"论文未给出实现细节"，不要编造

### 第4节：训练与优化过程

必须包含：
- 损失函数：公式 + 逐项解释 + 数字例子
- 优化器：类型 + 核心公式 + 参数设置（论文没写的标注"论文未涉及"）
- 学习率调度策略（如有）
- 数据划分方式
- 训练技巧（正则化、早停、数据增强等）

### 第5节：实验结果怎么看

必须包含：
- 数据集介绍：数据来源、规模、特征（比喻说明数据长什么样）
- 评价指标：每个指标的公式 + 计算方法 + 数字例子（准确率/精确率/召回率/F1 等基础指标也要解释，可用混淆矩阵手算）
- 主要结果：表格对比论文方法 vs 基线方法
- 消融实验：每个模块去掉后效果变化，说明什么
- **逐图逐表解读**：论文里影响结论判断的图/表（架构图不必）每张都要回答四个问题：横纵轴/表头分别是什么、基线是谁、趋势或差距说明什么、作者想用它证明哪句话。只堆数字不算解读
- 可视化结果解读（t-SNE、混淆矩阵、特征图等）要说明"图上的什么特征支撑了这个结论"

### 第6节：创新点与贡献

分点列出：
- 核心创新点（每点大白话解释）
- 与最接近的已有方法相比，"新"在哪里
- 客观区分：哪些是真创新，哪些是工程组合

### 第7节：局限性与可改进方向

必须包含：
- 论文方法的假设，这些假设在实际中成立吗
- 实验设置有没有"取巧"（数据划分是否合理、基线是否够强）
- 如果继续做，从哪几个方向改进
- **迁移性判断**：这个方法能迁移到液压电磁阀耦合故障诊断吗？需要改什么？如果论文领域离得很远（纯数学、金融、医学等），就如实说明迁移代价和不可迁移之处，**不要为了凑够这一点硬扯电磁阀**

### 第8节：核心公式速查表

表格形式，行与正文公式**一一对应**（编号集合必须完全相同，不许多一行也不许少一行）：

| 自编号 | 论文式号 | 模块 | 公式 | 一句话含义 |
|---|---|---|---|---|
| 式(1) | 论文式(3) | 特征提取 | $...$ | 把信号变成特征向量 |

- 正文每个公式都要有自己的 `式(n)`，全篇从 1 开始连续编号
- 论文式号照抄原文（可能是 (3)、(12)、(4a)），没有式号的写"论文无式号"
- 同一个公式在正文出现多次时，只在首次出现处编号，速查表也只列一行

### 第9节：小白FAQ

预判5-8个读者可能问的"蠢问题"，逐个回答。
例如："为什么要除以根号d_k？""为什么用交叉熵不用MSE？"

## 二、10条硬性要求（违反任何一条都算不合格）

1. **公式必须举例**：全文每一个公式都必须配手算数字例子；确实无法手算的按第五节"降级规则"明确说明原因，不许沉默跳过
2. **禁止跳步**：任何推导都写出中间步骤，不准写"化简得""整理得""显然""易知""同理可得"
3. **禁止黑话**：专业术语首次出现必须立即解释，并给中英对照
4. **比喻要贴切**：每个比喻都能映射回技术概念，不准为通俗而歪曲原意；必须简化时（如把 MMD 说成"两组均值的距离"）当场注明"这是简化版，严格定义是…"
5. **数字例子要极小**：用2-4个数据点、2×2矩阵，确保读者能跟着手算
6. **客观评价**：不准无脑吹论文，必须指出局限性和潜在问题
7. **联系研究方向**：在合适位置主动联系"液压电磁阀耦合故障诊断"；论文领域相距太远时，在第7节讲迁移可行性即可，不强行类比
8. **篇幅要足**：单篇论文精讲≥4500字、方法部分（第3节）≥2600字且占比≥55%；每节还要落在"九、字数预算"的区间内（防止第3节不足、FAQ 灌水）；篇幅是下限不是目标，禁止为凑字数重复灌水
9. **结构清晰且够形象**：严格按第0～9节输出，每节有明确标题，公式用LaTeX，代码用代码块；表格至少3张（对比、超参、形状、消融都行），插图至少1张（结构图/流程图/热图/对比图），图表都要编号并在正文里引用一次（"见表2""见图1"），细节见"十二、图表规范"
10. **不编造**：论文未提供的内容明确标注"论文未涉及，以下为推测"，不准编造成论文的原话或数据

## 三、公式讲解规范（三段式强制执行）

每个出现公式的地方，必须按以下顺序：

```
#### 【通俗理解】
（用比喻说清这个公式在干什么，不出现任何符号）

#### 【学术公式】
$$完整公式$$   式(1)（论文式(X)）
- 符号1：大白话解释
- 符号2：大白话解释
- ...
- 第一项：在惩罚/鼓励什么
- 第二项：在惩罚/鼓励什么

#### 【数字例子】
假设 xxx=...，yyy=...
第一步计算：... = ...
第二步计算：... = ...
最终结果：...
这个结果在实际中表示：...
```

## 四、数字例子设计原则

- **规模极小**：向量长度2-4，矩阵2×2或3×3，类别数2-3
- **数值简单**：用0、1、2、3这种整数，避免分数和小数干扰理解
- **可手算**：确保读者用纸笔能在1分钟内算完
- **有意义**：例子的结果要能映射回实际场景，不是纯数字游戏
- **覆盖边界**：如果公式有特殊情况（如除零、log(0)、除号分母为0），单独举例说明
- **算得对**：每个数字例子写完必须自己核对一遍算术；宁可换一组更简单的数，也不要出现算错

## 五、降级规则与质量自检清单

### 降级规则（无法满足硬性要求时，必须显式说明）

| 情形 | 处理方式 |
|---|---|
| 公式规模太大无法手算 | 用极端简化版（2×2、2-4个点、离散求和代替积分）演示，并注明"此处为演示用简化，论文真实规模为…" |
| 连简化都不可能 | 写"该公式涉及 XXX，无法手算演示，以下只解释各项作用"，不要用假数字冒充 |
| 论文未给出超参数/实现细节 | 标注"论文未涉及，以下为推测" |
| PDF 无文本层（扫描件） | 说明无法读取，请用户提供文本或 OCR 结果 |
| 论文领域与故障诊断相距很远 | 用论文自身领域比喻讲解，第7节说明迁移可行性，不硬扯电磁阀 |

### 质量自检清单（输出后逐项核对，共18项）

- [ ] 第0节有，且不超过3句话、无专业术语
- [ ] 第1节有研究对象比喻、已有方法不足、完整流水线图
- [ ] 第2节只讲了影响理解的核心概念，每个都有定义+比喻+数字例子
- [ ] 第3节模块顺序与论文一致，每个模块三段式齐全（层级见"八"）
- [ ] 每个公式都有自编号 式(n) 并标了论文式号，或已按降级规则说明无法手算
- [ ] 有公式的步骤都配了数字例子（或按降级规则豁免并注明原因）
- [ ] 全文没有"显然/易知/同理可得/化简得/整理得/不言而喻/众所周知"（搜一遍）
- [ ] 第4节损失函数有公式+解释+数字例子，优化器参数齐备或已标注缺失
- [ ] 第5节指标有公式+数字例子，有对比表、消融分析和逐图逐表解读
- [ ] 第6节区分了真创新与工程组合
- [ ] 第7节至少3条局限性，并给出能否迁移到液压电磁阀耦合故障诊断的明确结论
- [ ] 第8节速查表的 式(n) 编号集合与正文完全一致
- [ ] 第9节至少5个FAQ
- [ ] 关键公式和结论都标了论文出处（式号/图号/表号）
- [ ] 所有术语首现都有解释与中英对照；所有推测都标了"论文未涉及，以下为推测"
- [ ] 篇幅达标：全文≥4500字、第3节≥2600字且≥55%，每节字数在预算区间内
- [ ] 表格至少3张（对比/超参/形状/消融），每张都有"表 N"编号，且正文里至少引用过一次
- [ ] 插图至少1张（结构图或流程图优先），图注以"图 N"开头，正文里至少引用过一次

> 以上可机械判定的部分，交付前直接跑：`python scripts/check_output.py <精讲文件>`。脚本报 FAIL 就不许宣布完成。

## 六、用户研究背景（讲解时优先使用此领域的比喻）

用户研究方向：**液压电磁阀耦合故障诊断**

涉及技术领域：
- 信号处理（FFT、VMD、小波变换、时频分析）
- 机器学习与深度学习（CNN、Transformer、注意力机制、对比学习）
- 迁移学习与域自适应（DANN、MMD、对抗训练、半监督学习）
- 耦合故障诊断（多标签分类、故障解耦、盲源分离）
- 边缘计算与模型轻量化（剪枝、量化、知识蒸馏）
- 智能Agent与工作流编排

**比喻优先级**：优先用"振动信号""轴承故障""电磁阀""听诊器""流水线"等用户熟悉的场景做比喻，避免用NLP（文本分类）、CV（图像识别）等陌生领域做主要比喻。

如果论文本身是其他领域，先做"领域翻译"：把论文概念映射到故障诊断领域再讲解。例如：
- 论文的"图像分类"→ 映射为"振动信号分类"
- 论文的"文本情感分析"→ 映射为"故障严重程度评估"
- 论文的"域自适应（照片→素描）"→ 映射为"域自适应（实验室数据→工业现场数据）"

**注意**：领域翻译只用于帮助理解，不能改变论文原意。若论文领域与故障诊断相距太远（纯数学、金融、医学、人文社科），用论文自身领域的通俗比喻讲解，把"能否迁移到电磁阀场景"放到第7节讨论，并如实说明迁移代价。

## 七、论文类型路由与变体结构

**先判类型再套结构**。读完摘要、目录和方法开头就能判断，不要读完再回头改结构。

| 类型 | 识别信号 | 结构适配 |
|---|---|---|
| A 方法类 | 提出模型/算法，有独立"方法"节 + 实验对比 | 默认第0～9节 |
| B 综述类 | 标题含 review/survey/综述；大量文献分组讨论；没有自研模型 | 第3、4、5节替换 |
| C 理论/证明类 | 大量定理、引理、收敛性证明；实验很少或只做验证 | 第3、4、5节替换 |
| D 数据集/基准类 | 标题含 dataset/benchmark；核心是数据构造与评测协议 | 第3、5节替换 |
| E 应用/工程类 | 面向具体场景的系统设计，缺理论推导 | 弱化第3节公式，强化第1节流水线与第5节现场结果 |

**B 综述类**
- 第3节 → 文献脉络与分类框架：按方法族分组（不要按时间流水账），每族写"代表工作 + 解决了什么 + 硬伤"，末尾给一张分类框架图
- 第4节 → 这篇综述的取舍立场：它把哪些工作抬高了、漏掉了谁、分类维度是否自洽
- 第5节 → 证据强度：它的对比表是否同口径（数据集、指标、划分是否一致）

**C 理论/证明类**
- 第3节 → 定理与证明拆解：定理陈述 → 每个假设为什么需要（去掉会怎样）→ 证明思路（讲用了什么技巧，不要逐行抄）→ 结论的适用范围
- 第4、5节压缩为"假设与适用范围"，只保留用实验验证定理的部分

**D 数据集/基准类**
- 第3节 → 数据构造流程：采集条件、标注协议、划分方式、类别分布、标注一致性
- 第5节 → 基准设置与对比口径：谁在什么协议下跑的、能不能直接横比

**E 应用/工程类**
- 第3节可以没有大公式，但必须有"从输入到输出的每一步"，以及每一步在现场会遇到什么问题

**判定不确定时**：按 A 处理，在第0节末尾加一句"本文也可按 X 类理解"。不要为了套变体把方法类论文讲成综述。

## 八、标题层级映射与公式编号约定

标题层级固定，不许自创：

| 层级 | 用法 | 例子 |
|---|---|---|
| `#` | 全文唯一一级标题 | `# 论文精讲：基于XXX的YYY方法` |
| `##` | 每一节 | `## 第3节：论文方法逐模块精讲` |
| `###` | 方法模块 / 概念条目 | `### 步骤2：多尺度特征提取` |
| `####` | 三段式小节 | `#### 【学术公式】` |

公式编号：
- 正文每个独立公式（`$$...$$`）配自编号 `式(1)`、`式(2)`…，全篇从 1 连续编号
- 编号写在公式后：`$$...$$ 式(3)（论文式(7)）`
- 论文原文没有式号的写"（论文无式号）"
- 行内公式 `$...$` 不编号
- 第8节速查表"自编号"列必须是正文编号集合的**完全一致**拷贝：不许多一行，也不许少一行（`scripts/check_output.py` 会直接比对）

## 九、每节字数预算（中文字符）

| 节 | 预算 | 说明 |
|---|---|---|
| 第0节 | 50–240 | 超过3句就是违规 |
| 第1节 | 450–1200 | 流水线图不计入 |
| 第2节 | 450–1400 | 概念按需选，不是越多越好 |
| 第3节 | ≥2600 | 且≥全文55% |
| 第4节 | 270–1000 | 无训练过程（如非学习方法）可写"不适用" |
| 第5节 | 540–1600 | 逐图解读占大头 |
| 第6节 | 220–800 | 分点写，不要写成散文 |
| 第7节 | 300–900 | 至少3条局限 |
| 第8节 | 50–900 | 表格为主 |
| 第9节 | 300–1000 | ≥5个问题，不要凑数问答 |
| 全文 | ≥4500 | 下限不是目标 |

`scripts/check_output.py` 的 `BUDGET` 与本表逐格一致；改预算必须两边同时改。

预算是**纠偏工具**，不是切割线。某节确实没有内容（如理论论文没有实验节）时，写"本文无实验章节，原因是…"，不要硬凑到区间里；字数不足先补内容，不要靠拉长句子。

## 十、速览模式（brief）

用户说"速览 / 快速看看值不值得读 / 只要结论 / 先别展开"时，输出约 **800字**，不写满10节：

1. 一句话总览（同第0节）
2. 一页要点表：方法一句话 | 数据 | 指标 | 主要结论 | 最大局限
3. 值不值得细读：对哪类读者有用、对哪类没用
4. 结尾一句"要展开就告诉我讲哪节"

速览不配公式、不写数字例子、不写 FAQ——它存在的意义是**让用户在花4500字之前先做决定**。用户随后要细节时，按完整结构重写，不要把速览续写成四不像。

---

## 十一、模式路由：论文精讲 / 算法详解 / 速览

**先判模式，再动笔**。判错的代价是整篇结构返工：

| 模式 | 触发语 | 结构 | 篇幅下限 |
|---|---|---|---|
| **论文精讲 paper** | "精讲/精读这篇论文""这篇论文讲了什么" | 第0～9节（第一～七、十节） | 全文≥4500字，第3节≥2600字且≥55% |
| **算法详解 algorithm** | "把这个算法/项目讲透""从零讲清这个模型""我不读论文，就想要能复现的讲解" | 章结构（见下） | 全文≥4500字，公式所在章合计≥2600字且≥55% |
| **速览 brief** | "速览/值不值得读/只要结论" | 四件套（第十节） | 约800字 |

判定不清时的顺序：用户上传的是**论文 PDF** → paper；用户给的是**代码仓库/项目/课程作业/自己的实验** → algorithm；用户只要结论 → brief。两者都要时，先给 brief 再问走哪个。

### 算法详解模式（algorithm）的章结构

章数不固定，按内容长，但**顺序和必备内容固定**：

| 章 | 内容 | 必备 |
|---|---|---|
| 第0章 | 符号约定与整体地图：符号表 + 算法全景流程图 + 全文导读 | 是（公式多时） |
| 第1章 | 背景：这个算法解决什么问题，不做会怎样（可用自己的项目语言） | 是 |
| 第2章 | 数学地基：只讲后面真的会用到的概念，每个配比喻 + 手算 | 视算法难度 |
| 第3～k章 | 模块逐个拆：每个模块 = 它解决什么 → 公式逐符号 → 极小数字手算 → 代码对应 | 是（≥3章） |
| 第k+1章 | 训练/优化：损失、优化器、调度、数据划分 | 学习方法必备 |
| 第k+2章 | 基线/对比与评价指标：为什么和它比、每个指标怎么算 | 是 |
| 第k+3章 | 全流程小例子：一个真实样本从输入走到输出，每步都带数 | 是 |
| 末章 | 总结：设计思想一图流 + 什么时候别用这个算法 | 是 |

写法要求（与论文精讲一致，只是换成分章）：

- 每个模块章内必须有：**通俗解释**（可直接用 `> **通俗解释**：…` 引用块）+ **公式**（`$$…$$`）+ **手算例子**（2–4 个点、2×2 矩阵）
- 章标题格式：`## 第N章 标题` 或 `## N. 标题`，编号从 0 或 1 起**连续**
- 公式编号规则同第八节：`式(1)` 起连续，标注原文式号
- 禁用词、术语中英对照、"推测必须标注"等铁律不变
- 交付前用 `python scripts/check_output.py 文件.md --profile algorithm` 校验

## 十二、图表规范（"讲得形象"靠这一段）

文字讲得再清楚，读者脑子里也拼不出结构；一张图 + 一张表能省掉三段解释。硬指标：**表格 ≥3 张、插图 ≥1 张**（硬性要求第9条），`check_output.py` 的 S13/S14/S15 会查。

### 1. 表格：至少三张，每张都在回答一个问题

| 表格类型 | 回答什么问题 | 放在哪 | 例子 |
|---|---|---|---|
| 对比表 | 这篇论文和已有方法差在哪 | 第1节 | RNN / CNN / 自注意力的计算量、并行度、路径长度 |
| 超参表 | 模型到底多大、训练怎么设 | 第4节 | base 与 big 的层数、d_model、头数、dropout、参数量 |
| 形状表 / 维度表 | 张量是怎么流动的 | 第3节 | 八头注意力的 512 维如何切成 8 × 64 |
| 消融表 | 哪个设计真的有用 | 第5节 | 头数 1/4/8/16/32 对应的 BLEU |
| 结果表 | 到底赢了多少 | 第5节 | 各模型在 WMT14 英德/英法上的 BLEU 与训练成本 |
| 术语表 | 五个零件各是什么 | 第2节 | Q/K/V 三个角色 + 生活化类比 |
| 公式速查表 | 全部公式一览 | 第8节 | 自编号、论文式号、模块、公式、一句话含义 |

写法：

- 编号：`**表 4　八头注意力的维度切分**`，表号从 1 连续，不要跳号
- 表头必须一行，第二行是 `|---|---|` 分隔行
- 每个数字都能在原文找到出处；找不到就注明"论文未给出，此处为按公式推算"
- **表中每个表号都要在正文里被引用一次**（"见表 4"），否则 S15 报 WARN

### 2. 插图：至少一张，优先生成而不是找现成图

不要从论文 PDF 里截图（版权 + 分辨率 + 中文标注三件事都麻烦），用 `scripts/make_figures.py` 按 JSON 生成，保证 .md / .docx / .tex 三份产物看到的是同一张图。

四个子命令（都吃 JSON，都出 PNG）：

```bash
# 1) 结构框图：列式布局，适合"数据怎么流动"
python scripts/make_figures.py diagram spec.json -o figs/fig1.png --title "Transformer 整体结构"

# 2) 条形图：适合"和基线比一比"
python scripts/make_figures.py bar bleu.json -o figs/fig5.png --title "WMT14 英德 BLEU 对比" --ylabel BLEU

# 3) 折线图：适合"随步数/随超参怎么变"
python scripts/make_figures.py line curve.json -o figs/fig6.png --title "学习率随步数的变化"

# 4) 热图：适合"矩阵长什么样"（注意力权重、位置编码、混淆矩阵、相关矩阵）
python scripts/make_figures.py heat attn.json -o figs/fig4.png --title "注意力权重矩阵" --cmap Blues --vmin 0 --vmax 1
```

JSON 格式（三种，字段都可缺省）：

```json
// diagram：每列若干方框，列内竖连，前列末项指向后列首项
{"columns": [{"title": "输入", "boxes": ["源句 tokens", "词嵌入", "位置编码(+)"]},
             {"title": "编码器 ×6", "boxes": ["多头自注意力", "残差 + LayerNorm"]}]}

// bar：labels + series（每条一个颜色，可多条做分组对比）
{"labels": ["ConvS2S", "GNMT+RL", "Transformer big"],
 "series": [{"name": "英德 BLEU", "values": [26.36, 24.61, 28.4]}]}

// line / heat：line 用 {"x": [...], "series": [...]}；heat 用 {"matrix": [[...]], "xticklabels": [...]}
{"matrix": [[0.67, 0.24, 0.09]], "xticklabels": ["它", "喜欢", "猫"], "annot": true}
```

写进精讲的方式：

```markdown
![图 1 Transformer 整体结构：左边输入经编码器六层，右边解码器六层](figs/fig1_transformer.png)
```

- 图片放精讲同目录的 `figs/` 文件夹，引用写相对路径
- 图注必须 **以"图 N"开头**，一句话说清"读者该看出什么"，不要写"架构图"三个字了事
- 每张图在正文里至少引用一次（"见图 1"），并在图后写一两句怎么读这张图
- 图里的文字用中文（`make_figures.py` 已配好中文字体），坐标轴写清单位与含义

### 3. 三份产物怎么保持一致

`.md` 是唯一事实源；`.docx` 与 `.tex` 都从它导出，图片自动跟随：

```bash
python scripts/export_docx.py 精讲.md -o 精讲.docx
python scripts/export_tex.py 精讲.md -o 精讲.tex
```

导出脚本会把 `figs/` 里的图嵌进 docx（宽 15 cm、带斜体图注），或在 tex 里复制到 `figs/` 目录并生成 `\includegraphics` + `\caption`。所以**不要手动改 docx/tex 里的图**，改 md 再重新导出。

### 4. 什么时候可以少放图表

- 速览模式（brief）：不放图表，一张要点表就够
- 算法详解模式（algorithm）：表格仍要 ≥3 张，插图尽力而为（旧的精讲风格偏文字，因此 S13/S14 在该模式只报 WARN）
- 论文本身没有可视化素材、又实在画不出来时：如实写"本文没有可画的中间表征，以下用表格代替"，不要硬编一张看不出信息量的图
